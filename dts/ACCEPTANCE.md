# ACCEPTANCE —— 每道门的验收标准

推进规则:**过一门才开下一门;哪门不过,修完重过那门,不跳。**
每道门都有"不过怎么办"。诚实预期:首触(门1)后有一到两轮分钟级迭代,不是即插即用。

## 门 0 · 外部构建(mock,在本机)

范围:provision 状态机、幂等、dirty 恢复、evict/换版本清场、记账格式、extract 解析器。

通过标准:
- mock 端到端场景全绿:全新安装→ready;同构建重跑→**安装脚本零重跑**(计数器证明);
  注入失败→dirty→重试先清场再装→ready;evict→槽位路径清干净且拒绝清系统目录;
  装新构建未 evict 旧的→拒绝;并发第二把锁→拒绝;
- extract 对自造夹具(假 SQL 型/假 grtmgr 型单)字段全抽对,对不上的进 unmapped.log,零静默丢。

不过怎么办:在外面修,与黄区无关,不许带病进门。

## 门 1 · probe 首触(黄区,PROBE.md 走完)

通过标准:
- 拿回 SQL 型、grtmgr 型各 **1 份原样 dump**(哪一档都行);
- `config-facts.md` 有内容(哪怕一半"未知+在哪查");
- `preflight.log` 在手(红字清单就是本门的产出物)。

不过怎么办:哪步失败照 PROBE.md 兜底节记录;dump 拿不到时降 C 档;实在不行带回失败现象,
外面改 probe 脚本再进一次——**probe 成本半天,重进便宜**。

## 门 2 · 配置齐(preflight 全绿)

通过标准:按 config-facts.md 填完 `config.sh` 后,`preflight.sh` 无 ✗:
机器身份探活过、URL 模板拼出来的地址 wget 到头几个字节、安装阶梯引用的脚本在且可执行、
CLEAN_PATHS 前缀合法(拒系统目录)、健康检查命令可用、grtmgr 命令找得到。

不过怎么办:逐条红字改字段,分钟级迭代;字段本身拿不准的回 DTS/grtmgr 的 guide 文档抄。

## 门 3 · 冒烟(黄区,1 版本 × 1 单 × 3 次)

通过标准:
- 全链路走通:按版本搜→筛出 1 条→dump/解析→装版本→跑 3 次→落记录;
- 3 次结果**分 3 条**记(退出码+报错文本+耗时+执行到了哪步的标记);
- 记录里四点引擎标一致:单子(engine=gaussdb)→构建→实例健康检查→结果;
- 该单的处理车道(SQL/grtmgr)判对;判错的进 queue 也算过,但要在日志里留判型依据。

不过怎么办:断在哪环看 provision/运行日志指名道姓的报错;环境类回门 2,解析类改配置重跑解析
(**dump 已落盘,不重新抓网页**),执行类修 runloop 后只重跑该单。

## 门 4 · 首个整版本批

通过标准:
- 一个版本的全部合格单跑完,漏斗各级有数:该版本搜得 N → 集中式 M → 有材料 K → 跑了 J;
- 记账齐:六桶 + **环境失败桶** + queue/unmapped 账,**无静默丢弃**;
- 无"某单把实例打崩后,后续单全军覆没"——崩溃后 reset 生效,后续单正常;
- 中断重跑:跑到一半杀掉再来,已完成的单不重跑、已 ready 的版本不重装。

不过怎么办:数字异常(未跑完非 0、环境失败成片)先停,查环境再继续,不硬推。

## 门 5 · 放量(多个版本循环)

通过标准:版本外层循环按单量降序跑完 ≥3 个版本;换版本 evict→清场→装新,旧构建残留为零;
每版本独立收口记账;判定粘性生效(前次复现本次没跑出=偶现,不降级)。

## 通用红线(每道门都查)

- 安装脚本对 ready 构建**绝无重跑**(计数器/日志证明);
- CLEAN_PATHS 白名单外的路径绝无删除;
- 任何"字段对不上/判不了/单子定不了"都有账(queue/unmapped),零静默;
- 引擎标全程一致;compatibility 只出 A/B/M(GaussDB 白名单)。
